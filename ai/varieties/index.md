# 품종 연결

한국춘란의 형질 데이터와 실제 품종 정보를 연결하기 위한 영역입니다.

## 1. 기본 원칙

품종 연결은 기존 품종 JSON을 기준으로 합니다.

- `cultivar_class`: 사람이 도감에서 보는 품종의 대표 분류입니다.
- `classification`: 품종을 설명하는 주요 형질 축입니다.
- `traits`: 품종의 세부 관찰 정보입니다.
- `ai`: AI가 만든 보조 라벨과 메모를 관리하며, 공식 품종 정보와 중복 저장하지 않습니다.

형질 데이터가 품종 후보를 만드는 데 사용될 수는 있지만, AI의 후보 결과를 곧바로 공식 품종 정보로 저장하지 않습니다.

## 2. 연결 구조

품종 연결은 다음과 같은 흐름으로 관리합니다.

```text
형질 관찰
   ↓
형질 조합
   ↓
품종 후보
   ↓
기존 품종 JSON 확인
   ↓
사람의 검증
   ↓
검증된 품종 연결
```

기존 품종 JSON이 있는 경우 그 파일의 `id`와 기존 `classification`, `traits`를 기준으로 연결합니다.

새로운 품종 후보가 발견되었다는 이유만으로 품종 JSON을 자동 생성하지 않습니다.

## 3. 무엇을 연결하는가

품종과 형질의 관계는 크게 세 층으로 구분합니다.

### 대표 분류

`cultivar_class`는 품종의 대표 분류입니다.

대표 분류와 세부 형질을 하나의 계층으로 합치지 않습니다.

### 주요 형질 축

`classification`에 저장된 형질 축을 사용합니다.

현재 확인된 엽예 형질 축은 다음과 같습니다.

- `leaf_form`
- `pattern`
- `leaf_tip`
- `pattern_position`
- `pattern_timing`

이 값들은 현재 저장소의 분류 표준을 기준으로 합니다. 새로운 값을 임의로 만들지 않습니다.

### 세부 관찰 정보

`traits`에는 실제 품종에 대해 확인된 세부 관찰 정보를 기록합니다.

예를 들어 현재 품종 데이터에서는 잎의 길이, 폭, 두께, 형태, 잎끝, 질감, 기본 잎색, 무늬 색 등의 필드가 사용되고 있습니다.

## 4. AI 후보와 공식 품종 정보의 분리

AI가 이미지에서 품종 후보를 만들 수 있지만, 후보와 확정된 품종은 서로 다른 상태입니다.

```text
AI 관찰 결과
   ↓
후보 품종 A / B / C
   ↓
자료 및 기존 품종 정보 대조
   ↓
사람의 확인
   ↓
공식 품종 연결
```

후보 단계에서는 불확실성을 유지합니다. 사람이 확인하기 전에는 기존 품종의 공식 `classification`이나 `traits`를 후보 결과로 덮어쓰지 않습니다.

## 5. 이미지 데이터셋과의 연결

향후 이미지 데이터셋에서는 하나의 이미지가 특정 품종으로 바로 확정되지 않을 수 있습니다.

따라서 다음 정보를 분리해서 관리합니다.

- 이미지에서 관찰된 형질
- OCR로 추출된 품종명 후보
- 이미지와 연결된 품종 후보
- 사람이 검증했는지 여부
- 검증된 경우의 최종 품종 연결

이 구조를 통해 원본 관찰 결과와 최종 확정 정보를 구분할 수 있습니다.

## 6. 확장 원칙

품종 연결 구조를 확장할 때는 다음 순서를 따릅니다.

1. 기존 품종 JSON과 현재 분류 표준을 확인합니다.
2. 형질 데이터와 품종 정보의 관계를 확인합니다.
3. 후보와 확정 정보를 구분합니다.
4. 사람이 검증해야 하는 항목을 별도로 유지합니다.
5. 기존 품종 JSON의 구조를 우선 사용합니다.
6. 기존 데이터와 중복되는 새로운 연결 필드를 만들지 않습니다.

현재 단계에서는 실제 품종 연결 데이터를 새로 생성하지 않습니다. 실제 자료가 확인된 후 기존 품종 데이터에 연결합니다.

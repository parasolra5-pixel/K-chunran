# K-Chunran 화예·예(藝) 데이터 모델 초안

> 상태: 설계 초안
>
> 목적: 화예 도감의 분류와 실제 난이 가진 예(藝), 그리고 각 예의 발현 표현을 분리하여 기록한다.
>
> 원칙: 용어가 확인되기 전에는 기존 분류 데이터나 예품수 계산 규칙을 임의로 확정하지 않는다.

## 1. 핵심 구분

K-Chunran에서는 다음 세 가지를 분리한다.

1. **도감 분류**
   - 사용자가 찾아보기 위한 탐색 체계
   - 예: 홍화, 주금화, 황화, 복륜화, 두화, 소심 등

2. **관찰 형질**
   - 사진이나 실물에서 실제로 관찰되는 표현
   - 예: 잎의 복륜, 꽃의 복륜 무늬, 두화 형태, 설판의 소심 표현

3. **예(藝)**
   - 하나의 난에 존재하는 독립적인 예
   - 예품수는 서로 다른 예의 개수를 기준으로 표현한다.

따라서 도감에 `복륜화`가 하나의 항목으로 존재한다고 해서 `복륜화`를 별도의 예로 다시 세지 않는다.

## 2. 복륜 사례

복륜은 하나의 예이며 잎과 꽃에서 각각 발현될 수 있다.

~~~text
복륜
├─ 잎에서 발현 → 복륜엽
└─ 꽃에서 발현 → 복륜화

= 1예
~~~

즉, **복륜엽 + 복륜화 = 2예가 아니다.**

이 관계는 K-Chunran 데이터 모델에서 반드시 보존해야 한다.

## 3. 복합 예 사례

서로 다른 예가 추가되면 예품수가 증가한다.

~~~text
복륜
├─ 잎 → 복륜엽
└─ 꽃 → 복륜화

소심
└─ 꽃 → 소심

→ 2예품
→ 복륜소심
~~~

~~~text
복륜
├─ 잎 → 복륜엽
└─ 꽃 → 복륜화

두화
└─ 꽃 → 두화

소심
└─ 꽃 → 소심

→ 3예품
→ 복륜두화소심
~~~

다만 이 절의 예품수 사례는 **한국춘란 현장 용례를 기준으로 한 초기 검증 사례**이며, 모든 화예 용어에 일반화하기 전에 개별 용어와 관계를 계속 검증한다.

## 4. 데이터 관계

초기 모델은 다음 관계를 전제로 한다.

~~~text
품종
 └─ 예
     ├─ 예 이름
     ├─ 발현 위치
     │   ├─ 잎
     │   └─ 꽃
     └─ 표현형
         ├─ 복륜엽
         └─ 복륜화
~~~

예를 들어:

~~~text
예: 복륜
발현:
  - leaf → 복륜엽
  - flower → 복륜화
~~~

별도의 예:

~~~text
예: 소심
발현:
  - flower → 소심
~~~

품종에 연결된 예의 수로 예품수를 표현한다.

## 5. 예품수 계산 원칙

초기 검증 사례:

| 예의 구성 | 예품수 |
| --- | ---: |
| 복륜 | 1예품 |
| 두화 | 1예품 |
| 소심 | 1예품 |
| 복륜 + 소심 | 2예품 |
| 두화 + 소심 | 2예품 |
| 복륜 + 두화 + 소심 | 3예품 |

중요:

**같은 예의 여러 발현 위치는 예품수를 증가시키지 않는다.**

예:
- 복륜엽 + 복륜화 → 복륜 1예

단, 특정 형질이 독립적인 예인지, 단순한 표현형인지, 또는 다른 예와 결합된 하나의 표현인지 확인되지 않은 경우에는 예품수를 자동 계산하지 않는다.

## 6. 일본 등록자료와의 비교 기준

일본의 전국일본춘란연합회 등록자료에서는 **`花物`이 실제 등록 분류명으로 사용된다.** 예를 들어 2023년 등록품 `望月`은 공식 원문에서:

~~~text
韓国春蘭（花物）　黄花素心
~~~

으로 등록되어 있으며, 형태는:

~~~text
黄花素心の荷花弁
~~~

으로 기록되어 있다.

여기서 K-Chunran이 보존해야 할 층위는 다음과 같다.

~~~text
원문 등록 표현
└─ 韓国春蘭（花物） 黄花素心

구조화
├─ 계통: 韓国春蘭
├─ 일본 등록 분류: 花物
├─ 등록 표현: 黄花素心
├─ 관찰 형질: 황화
├─ 관찰 형질: 소심
└─ 꽃 형태: 荷花弁
~~~

중요:

**일본 등록 분류인 `花物`을 K-Chunran의 '꽃 분류' 또는 '예(藝)'와 동일한 개념으로 취급하지 않는다.**

또한:

**`黄花素心`이라는 표현에 황화와 소심이라는 두 형질이 들어 있다고 해서 이를 자동으로 `2예품`으로 계산하지 않는다.**

실제 일본 공식 등록목록에서는 `花物`과 별도로 `複芸`이라는 등록 분류가 사용된다. 따라서 `花物`, `複芸`, 개별 형질, 예(藝), 예품수는 서로 다른 데이터 층위로 보존해야 한다.

### 일본 자료를 K-Chunran에 적용하는 원칙

일본 자료를 가져올 때는 다음 순서로 기록한다.

~~~text
원문
 ↓
출처의 등록 분류
 ↓
관찰/기술된 형질
 ↓
발현 위치
 ↓
예 관계
 ↓
예품수
~~~

특히 `花物`, `柄物`, `複芸`은 **출처의 등록체계에 속한 분류 정보**로 먼저 보존하고, K-Chunran의 예품수 계산에 직접 대입하지 않는다.

## 7. 확인된 현장 용례

2024년 경남신문의 한국춘란 설명에서는 꽃의 예를 색깔·무늬·형상 등에 따라 구분하고, 두화에 소심이 더해진 `두화소심`을 2예품, 복륜·두화·소심이 함께 나타나는 `복륜두화소심`을 3예품으로 설명한다.

출처:
- https://www.knnews.co.kr/news/articleView.php?gubun=photo&idxno=1427843

이 자료는 현장 용례를 확인하는 근거로 사용하며, 모든 화예 용어의 공식 표준을 단독으로 확정하는 근거로 사용하지 않는다.

## 8. 아직 확정하지 않는 항목

다음 용어는 도감에 존재하더라도 예품수 계산 규칙을 별도로 검증한 뒤 데이터 모델에 확정한다.

- 홍화
- 주금화
- 황화
- 백화
- 도화
- 자화
- 복색화
- 산반화
- 호화
- 원판화
- 기화
- 색설화
- 중투화
- 투구화
- 기타 복합 표현

특히 다음은 구분해서 조사한다.

- 용어가 독립적인 화예 분류인가?
- 하나의 독립적인 예로 계산되는가?
- 다른 예와 결합할 때 2예·3예로 어떻게 표현되는가?
- 잎의 예와 꽃의 표현이 같은 예의 발현 관계인가?
- 단순한 표현형 또는 형태 설명인가?
- 출처의 등록 분류인가, K-Chunran의 관찰/분류 개념인가?

## 9. K-Chunran 구현 원칙

현재 단계에서는 다음 파일의 분류 체계를 이 문서만을 근거로 변경하지 않는다.

- `_data/categories.yml`
- 화예 도감 목록
- 개별 품종 데이터

먼저 실제 용례를 조사하고 검증된 관계를 축적한다.

그 다음 데이터 스키마를 확정한다.

권장 처리 순서:

~~~text
실제 용어 조사
    ↓
예와 표현형 관계 검증
    ↓
예품수 규칙 검증
    ↓
출처 등록 분류와 K-Chunran 분류의 층위 분리
    ↓
데이터 스키마 확정
    ↓
샘플 품종 데이터 적용
    ↓
화면 표시
    ↓
AI 데이터 구조 연결
~~~

## 10. AI 데이터와의 연결

향후 AI가 직접 `3예품`을 먼저 예측하도록 만들지 않는다.

권장 흐름:

~~~text
사진
 ↓
관찰 형질
 ↓
발현 위치와 표현형
 ↓
예 관계 해석
 ↓
예 목록
 ↓
예품수
 ↓
품종 후보
~~~

예:

~~~text
사진
 ↓
잎의 복륜 관찰
꽃의 복륜 관찰
꽃의 두화 관찰
꽃의 소심 관찰
 ↓
복륜 + 두화 + 소심
 ↓
3예품
~~~

이렇게 하면 하나의 예가 여러 기관에서 발현되는 경우와 서로 다른 예가 결합되는 경우를 구별할 수 있다.

## 11. 설계 원칙 한 문장

> **K-Chunran은 '도감 분류', '관찰 형질', '예(藝)', 그리고 출처의 등록 분류를 분리하고, 하나의 예가 여러 위치에서 발현되는 관계를 보존한 뒤 검증된 규칙에 따라 예품수를 계산한다.**
